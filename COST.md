# Cost Architecture and Adaptive Economic Control

Cost is not a FinOps layer attached after the architecture is built. It is encoded into the architecture from the first design decision.

## 1. Economic invariant

The system should use **the cheapest computational class that can correctly satisfy the obligation**, while continuously learning where each class is actually sufficient.

```text
deterministic computation
    -> Jev semantic computation
    -> local model where proven sufficient
    -> prepaid scheduled cognition
    -> metered premium API
```

This is not a rigid ladder. Urgency, quality, risk, waiting time, and critical-path impact remain part of the decision.

## 2. Do not pay for continuity

A workflow may remain logically alive for weeks while premium cognition is active for only minutes. Waiting state is persisted rather than embodied by a resident model.

> **Project duration is not premium-model runtime.**

## 3. Pay only at cognitive gaps

The system spends premium cognition on the unresolved `???`, not on the deterministic trajectory surrounding it.

```text
known -> known -> ??? -> known -> known
```

## 4. Prepaid cognitive capacity

Platform subscriptions and scheduled tasks can act as periodic prepaid capability when available within their normal product constraints.

They are **economically preferred supply, not a correctness dependency**.

If a scheduled appearance is missed, the Cognitive Interrupt remains durable. If waiting is unacceptable, the Engine may escalate to API supply.

## 5. API as reliability and novelty backstop

Metered premium API exists for:

- stalled workflow recovery;
- novel failures;
- critical-path acceleration;
- missing compatible subscription capacity;
- time-sensitive work;
- bootstrap mistakes in planning or continuation design.

The target is not API usage of exactly zero. The target is:

> **API exceptional rather than operational.**

## 6. Early spending can be rational

During bootstrap the system knows little about its own failure modes. It may pay aggressively for API rescue to preserve liveness and discover the structure it needs.

Every rescue should create pressure to eliminate its own recurrence.

```text
API rescue
 -> evidence
 -> root cause
 -> Template / Workflow / JevPack / deterministic check
 -> fewer future rescues
```

## 7. Cost-aware planning

Planning should explicitly consider:

- capability;
- quality;
- wait time;
- marginal monetary cost;
- historical success;
- criticality;
- serial interrupt depth;
- reusable artifacts already present.

A cheap local decision can be globally expensive if it creates three extra premium waits later.

## 8. Preparation protects premium windows

Before a premium window arrives, deterministic work should prepare:

- logs;
- benchmarks;
- relevant files;
- compact context;
- unresolved questions;
- output schema;
- completion criteria;
- required artifacts.

Premium cognition should arrive to a prepared workstation.

## 9. Continuation quality is economic quality

A cognitive turn that requires another expensive turn merely to interpret its output is costly even if its prose is excellent.

Useful economic metrics include:

- **Continuation Readiness**
- **Deterministic Runway**
- **Handoff Repair Cost**
- **Serial Interrupt Depth**
- **Expected Cognitive Wait**

## 10. Templates capitalize cognition

When a repeated cognitive pattern becomes a template, previously paid reasoning becomes reusable structure. Templating is therefore a form of capital accumulation.

## 11. Content addressing prevents duplicate spend

Content identity allows the system to reuse exact work, artifacts, and structure instead of re-investigating equivalent objects.

## 12. Braintrust as empirical accounting

Cost should be correlated with outcome, not only token usage.

Useful views include:

```text
TaskType x executor x quality x latency x cost
WorkflowRevision x outcome x interrupts x cost
JevPack x calibration x cost
Template x downstream quality x repair cost
```

## 13. Economic metrics

The Engine should make cost legible at several levels rather than reducing economics to token counts. Useful measures include:

- **Total Cognitive Cost**
- **Cost per Successful Task**
- **Premium Dependency**
- **Interrupt Rate**
- **API Rescue Rate**
- **Rescue Recurrence**
- **Rescue Compilation Rate**
- **Subscription Utilization**
- **Deterministic Runway**
- **Cognitive Compression**
- **Handoff Repair Cost**
- **Serial Interrupt Depth**
- **Expected Cognitive Wait**

The most useful recurring question is not merely "how much did we spend?" but **"why are we still paying for cognition here?"**

## 14. Adaptive control

Economic routing is not configured once.

```text
policy_t
 -> executions
 -> Braintrust evidence
 -> evaluation
 -> policy patch
 -> policy_t+1
```

Prices, models, subscriptions, local capability, templates, and workflows all change. Economic control must therefore remain continuous and empirical.

## 15. Maturity curve

Bootstrap:

```text
API frequent
premium frequent
few templates
many planning errors
```

Learning:

```text
more templates
more Jev
better task boundaries
API declining
```

Maturity:

```text
deterministic majority
Jev frequent
subscription cognition targeted
API rare and intentional
```

The program is economically mature when premium dependence and rescue recurrence fall **without** degrading quality, reliability, or objective progress.

## 16. Final economic principle

> **The system buys intelligence only where it has not yet learned how to turn that intelligence into software.**
